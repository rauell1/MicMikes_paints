## Paint Visualizer

Three-tier system — fastest path wins:

1. **Pre-generated JPEG** — 100 images (`public/pregenerated/{roomId}_{colourId}.jpg`), served as static assets, instant load. Generated by `scripts/pregenerate.ts` using AI wall masks.
2. **Canvas recolor** — Client-side HSL pixel manipulation using the room's `wall_mask` polygon from the DB. Falls back to this if no pre-gen image exists.
3. **Original photo** — Shown as-is if both above fail (CORS or no mask).

### AI Wall Segmentation

Wall masks are generated by running `nvidia/segformer-b5-finetuned-ade-640-640` locally via the HuggingFace `transformers` library. The model is trained on ADE20K (150 semantic classes, class 0 = wall) and runs entirely on CPU — no API key or cloud cost needed.

```bash
# Regenerate wall masks for all 5 rooms
python scripts/segment_rooms.py

# Regenerate all 100 pre-gen JPEGs
node --env-file=.env --import=tsx/esm scripts/pregenerate.ts
```

Requires Python 3.10+ with `torch`, `transformers`, `pillow`, `numpy`, `requests`.

### Before/After Slider

Drag slider to compare original vs. painted room. Uses `clipPath: inset()` on a canvas-rendered painted version overlaid on the original `<img>`.

## Database

**Neon PostgreSQL** · project `lucky-flower-14546790`

Tables: `products`, `variants`, `colours`, `rooms`, `orders`, `order_items`, `order_events`, `cart_events`

- Prices in KES as integers (whole shillings)
- UUIDs everywhere, no auto-increment IDs
- `rooms.wall_mask` — semicolon-delimited normalized polygon coordinates (fallback when no pre-gen image)

## API Routes

```
GET/POST/PUT/DELETE  /api/admin/colours
GET/POST/PUT/DELETE  /api/admin/products
GET/PUT              /api/admin/variants
GET/POST/PUT/DELETE  /api/admin/rooms
GET/PUT              /api/admin/orders
GET/POST/DELETE      /api/admin/login      (cookie auth)
POST                 /api/cart-events
POST                 /api/recolour         (server-side image recolor using PNG masks)
POST                 /api/mpesa/stkpush
POST                 /api/mpesa/callback
GET                  /api/mpesa/status/[id]
```

> **Vercel Function Isolation:** Each `.ts` file in `/api` is compiled independently. Shared imports from `/api/_lib` do NOT work at runtime. Auth logic (`verifyAdminToken`) must be inlined in each admin route file.

## Order Flow

```
pending → awaiting_payment → paid → approved → processing → shipped → delivered
```

Every status change is logged to `order_events` with actor, IP, and metadata.

Invoice format: `INV-YYYYMMDD-XXXX`

---

## Event Tracking

`cart_events`: `product_view`, `swatch_click`, `visualizer_open`, `add_to_cart`, `remove_from_cart`, `checkout_start`

`order_events`: `payment_initiated`, `payment_success`, `order_created`, `approved`, `shipped`, `delivered`

## Key Rules

- KES prices as integers (whole shillings, no decimals)
- M-Pesa phone numbers in `2547XXXXXXXX` format
- Every cart action → `POST /api/cart-events`
- Every order status change → `INSERT order_events`
